# Library quality program

Owner direction, 2026-09-11: make Library useful enough that a person would choose
Atlas for Library alone. Incoming originals should contribute to connected,
maintained knowledge that a later reader can inspect, question, correct and reuse.
The owner selected a question-led entrance with explicitly refreshed retained
answers. General knowledge remains distinct from approved code ontology.

This is an active program, not a claim that the product has reached that standard.
Astra owns product decisions, evidence interpretation and final qualification.
Bounded implementation can run in parallel on Luna max, with isolated ownership
and the same required checks. Community reports inform hypotheses; neither a
popular post nor a passing internal test establishes demand.

## Delivery order

| Slice | Human ability | Evidence required before promotion |
|---|---|---|
| Retained questions and revisions | Recover a saved answer after its evidence changes | Exact previous text preserved; changed/missing/new evidence visible; compare and create-only save; independent later-reader walk |
| Inspectable citations | Move from a statement to its original and exact location | Known citations open the right original; missing targets stay explicit; no false source-read receipt |
| Faithful ingestion | Trust what a long or mixed-format original contributed | Coverage and partial reads visible; figures/tables/qualifiers retained; a difficult-source comparison against the originals |
| Accumulating knowledge | New material updates relevant existing knowledge | Forward/reverse arrival, contradictions, duplicate topics and human edits tested; no silent claim replacement |
| Sustainable maintenance | See and resolve what needs attention without rebuilding everything | Impact scope, unresolved items and completion derived from files; bounded work and no idle model calls |
| Standalone usefulness | Complete recurring knowledge work without code nodes or prior chat | Documents-only onboarding, repeated real tasks, held-out questions and direct owner feedback |

Each slice starts with the smallest reproducible failure. Do not expand the
feature list to substitute for demonstrating the current slice. Keep raw sources,
source-specific write-ups, retained interpretations and approved ontology meaning
under their existing distinct authorities.

## Execution routes

The owner's explicit requirement includes ACP coding agents such as Claude Code
and Codex. Library must not be designed or qualified as local-LLM-only. Keep ACP
and local/connected model execution as explicit routes with their own capability,
transfer, streaming, cancellation and write-review contracts. A shared transport
fixture does not prove both real adapters work; qualify each supported adapter
separately and name any missing configuration or capability honestly.

## Qualification

Research on 2026-09-11 covered twelve directly opened discussions across Reddit,
Hacker News and the Obsidian Forum; the [discussion ledger](../benchmark/LIBRARY-COMMUNITY-2026-09-11.md)
records their provenance and falsifiers. [Karpathy's LLM Wiki proposal](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
supplies the accumulation hypothesis. A [long-PDF recall failure report](https://www.reddit.com/r/LocalLLaMA/comments/1ps6txq/rag_that_actually_works/)
motivates testing buried facts and distinguishing uninspected material from
absence. A [large-vault maintenance report failure](https://forum.obsidian.md/t/vault-inspector-find-broken-links-and-orphan-attachments/114637)
motivates bounded reports and recovery tests. These are reported experiences,
not independently established causes or evidence that Atlas solves them.

Evaluate accuracy, provenance, uncertainty, preserved intent, revision recovery
and actual task completion separately. Include a raw-source control and the
current Library baseline using the same questions. Measure the page a reader is
likely to open first, not only answers produced by reading an entire tiny corpus.

Required adversaries include a newer conflicting document, an older document
arriving last, a changed original, a missing original, partial extraction, a
concurrent human edit, and competing answer revisions. A hash match establishes
byte currentness only. A template-valid page is not necessarily true.

Use fresh readers without the generating conversation for handoff claims. Label
transport stubs, synthetic answers and familiar corpora explicitly. They prove
particular mechanics, not autonomous synthesis quality. Record unresolved
questions and unsupported claims instead of hiding them in a combined score.
Time, model calls and tokens are operational diagnostics; they cannot compensate
for lost meaning or unsupported conclusions.

## Operating boundaries

- Work in this repository and assigned scratch folders. Preserve unrelated work.
- Do not replace the owner's installed app, publish, or accept new ontology
  meaning without the applicable authorization. A private review build is a
  separate proof surface.
- Do not send messages to communities. Research is read-only.
- Keep a source ledger identifying firsthand experience, promotion, duplicated
  posts, inference and untested opinion. Turn a report into a candidate only when
  it changes a concrete product hypothesis or verifier.
- Finish a selected implementation through required checks, rendered evidence,
  the routed review and documentation. Do not describe orientation as delivery.
- If a human decision is missing, prepare its exact proposal while continuing
  independent authorized work. Passing time is not acceptance.

The program closes only when the agreed workflows are delivered and qualified,
and the owner has assessed Library on recurring real work. Until then, report
bounded milestones and remaining evidence rather than a world-class verdict.
